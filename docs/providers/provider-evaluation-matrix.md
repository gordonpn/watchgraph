# TV and movie provider evaluation

Research for [#140](https://github.com/gordonpn/watchgraph/issues/140), accessed **2026-11-11**. This is a provider selection and adapter requirements document; it does not enable an integration or change existing MAL behavior. Provider policies can change: recheck these sources before implementing or releasing an adapter.

## Decision

Use **Trakt as the primary authorized user history provider for TV and movies**, and **TMDB as the intended metadata and candidate discovery provider**, subject to the licensing and verification gates below. Use **TVmaze as an optional TV episode/schedule enrichment source**, with separate provenance and license handling. Neither TMDB nor TVmaze's free public API substitutes for Trakt's cross-media history synchronization.

Trakt's current official documentation confirms PKCE support, but contradicts the issue's suggested quota: Standard GET requests have **500 calls per five minutes**, not 1,000. Developer **Premium** and user **VIP** are different subscriptions. TVmaze also has a paid user API, so the absence of history applies to its **free public API**, not every TVmaze product.

TMDB is a conditional selection: its currently published terms prohibit use in connection with an ML/AI application and making derivatives of TMDB content. Do not assume permission for embedding generation, model training, derived scores, or other recommendation processing. Resolve the intended ranking use against those restrictions before implementation; use provider-supplied discovery results only within the applicable permission. The terms also impose a **six-month cache maximum**, which must override any indefinite stale-cache fallback.

These are adapter targets, not assertions that authenticated live requests were run. No provider credentials were used.

| Trakt progress | `GET /shows/{id}/progress/watched`, `/sync/playback/movies`, `/sync/playback/episodes` | Checked official contract [R8]. Watched episode completion and paused playback percentage are different signals. History is not equivalent to playback progress. |
| Trakt sign-in | `https://auth.trakt.tv/oauth/authorize`; `POST /oauth/token`; device `POST /oauth/device/code` and `/oauth/device/token` on the same auth host | Checked PKCE guide and OAuth contract [R2, R8]. Production PKCE redirects require HTTPS on an owned domain: **no localhost or custom schemes**. Development redirects are more permissive. Trakt production registration also requires a privacy policy, attribution evidence, app details and expected usage. Standard production access requires review; this is distinct from the API Use Policy permitting compliant integration uses without an individual commercial agreement. Treat user VIP/locked accounts and endpoint-specific restricted access as capability checks, not evidence that every endpoint is available on Standard.

## Proposed client budgets and cache policy

The following are **Watchgraph design defaults**, not provider promises. Future adapters should use separate provider limiters rather than copying MAL's retry/cache policy unchanged.

| Provider | Conservative starting budget | Practical request planning |
| --- | --- | --- |
| TMDB | 2 requests/sec, burst 1, maximum 2 concurrent calls; configurable after official rate verification | A cold run with 5 discovery pages and 100 detail cache misses costs 105 calls, at least about 53 seconds at this design rate, excluding latency/retries. Fetch only selected candidates, reuse details and consolidate requests only where officially supported. |
| TVmaze | 1 request/sec, burst 1, maximum 1 in flight, coordinated across calls sharing a public IP | 50 shows using one details and one episode-list request each cost 100 calls, at least about 100 seconds. Use documented embedding when appropriate to reduce calls; do not poll more rapidly than upstream cache freshness. Multiple CLI processes behind one IP share risk. |
| Trakt | GET: rolling window capped initially at 400/300 sec per documented bucket, paced at 1/sec, burst 1. Writes: at most 1/sec, separate queue | History reads cost `ceil(movie events / page size) + ceil(episode events / page size)` plus an activity check. For an **illustrative**, not guaranteed, page size of 100, 500 movie events + 2,000 episode events costs 26 GETs. Confirm endpoint page bounds first. Per-show progress hydration adds one call per show and must be explicitly budgeted. |

On every provider, count pagination, retries, metadata hydration and background work against the same bucket. De-duplicate concurrent identical requests; never create keys or apps to bypass limits. A per-process limiter is insufficient for concurrent processes sharing a provider bucket: coordinate where possible or disclose the limitation and back off across the affected requests.

For Trakt, read `X-Ratelimit` when present (`name`, `period`, `limit`, `remaining`, `until`), reduce the available budget and pause until reset when exhausted. Keep user and unauthenticated client/IP buckets separate. Premium switching is a deliberate configuration/capability decision, not an automatic failover to `apiz.trakt.tv`. Never assume user VIP grants developer throughput.

For 429, respect `Retry-After` when supplied; otherwise use bounded exponential backoff with jitter (proposed 2, 4, 8 seconds, at most three retries), then surface a resumable failure. Trakt explicitly warns that security-layer 429 responses can omit **both** rate headers. Honor a longer reset delay without blocking an interactive command indefinitely: checkpoint and report when it can resume. Use bounded retries for transient reads; do not blindly replay history writes after ambiguous timeouts, because that can duplicate plays. Fail authentication/permission errors clearly; token renewal must be a separate, bounded flow. Log provider, method, endpoint template, status, request count and rate headers, excluding credentials and private history payloads.

Proposed local TTLs: discovery/search 1 hour, current TV schedules/episodes 1 hour, stable metadata 7 days, user history/activity 15 minutes or explicit refresh. These are freshness targets, not contractual retention limits. Fetch history incrementally using the documented activity/timestamp mechanisms, but reconcile deletions and changed events periodically; a forward-only timestamp cursor cannot detect every removal. Commit sync checkpoints only after complete pagination succeeds.

Use provider-keyed caches and provenance on normalized fields. For TMDB, add a hard maximum retention based on fetch time of **six calendar months**, including stale fallback, derived copies and artwork; purge rather than serving beyond that boundary. Track content separately from independently obtained IDs/user history, and purge required content on revoked/terminated access. For Trakt, scope private caches by account, stop remote access on disconnect, provide deletion controls, cache images, and distinguish convenient nested list metadata from fresh summary data [R7]. Never combine provider catalogs into a redistributable dataset without assessing each license.

## Implementation gates and limitations

- **TMDB technical verification remains open:** official developer auth, quota and endpoint references returned 403 from this research environment. The public API terms were readable. The 40–50 requests/sec estimate in #140 is therefore not treated as verified, and no daily/monthly quota or exact free-tier throughput is claimed. Confirm with current official docs or the provider before implementing the adapter.
- **TMDB licensing is a real scope gate:** confirm whether Watchgraph's intended discovery/ranking workflow is permitted, including the ban on derivatives and ML/AI use, the commercial-use agreement, logo presentation and content retention. A metadata-source preference is not a claim that every planned recommendation technique is authorized.
- **Trakt production CLI authorization:** PKCE is officially supported; the existing MAL localhost callback cannot simply be reused for a production Trakt app. Select device flow or an owned HTTPS callback, register production access and verify endpoint access without assuming a VIP subscription solves it.
- **TVmaze redistribution:** retain CC BY-SA provenance and review ShareAlike obligations for any adapted database exports; the free public API covers TV metadata, while the paid user API is a separate evaluation.
- No authenticated API calls, quota exhaustion tests, pricing checkout, production registration or legal permission were performed. Costs for paid/commercial arrangements and Premium limits must be checked at adoption time. This research neither purchases a plan nor changes application configuration.
